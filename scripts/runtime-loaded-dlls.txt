# DLLs that QEMU opens with LoadLibrary() at run time instead of importing.
#
# Both Windows packagers -- scripts/win64-dist.sh and scripts/nsis.py -- find
# the DLLs they have to ship by walking the PE import table ("objdump -p", the
# "DLL Name:" lines).  A library that is never imported, only dlopen()ed, does
# not appear there at all, so an import-table walk is structurally incapable of
# finding it: it has to be named here instead.
#
# Only the runtime-loaded DLLs themselves belong here.  Whatever they *import*
# (their C++ runtime, zlib, ...) is resolved by the ordinary recursive import
# walk once the file has been copied.
#
# Entries are searched for in the same directories as imported DLLs.  A name
# that is found nowhere is skipped with a warning and is not an error, so a
# sysroot that does not have an optional runtime dependency still packages.
#
# Blank lines and '#' comments are ignored.
#
# The list is currently empty.  It held ANGLE's libEGL.dll and libGLESv2.dll,
# which libepoxy resolves lazily through LoadLibrary() -- the case that made
# this mechanism necessary in the first place.  The win32 display backend no
# longer has a GL path, so nothing in a Windows build LoadLibrary()s anything
# any more.  The mechanism is kept because the problem it solves is structural
# and will come back the next time something is loaded rather than imported.
